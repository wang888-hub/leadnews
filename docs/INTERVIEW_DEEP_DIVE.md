# 面试深挖题库

每题包含核心答案和常见误区，回答时应结合仓库真实实现，不背抽象口号。

## 架构与工程

### 1. 为什么是微服务而不是单体？
- 核心答案：领域的数据所有权、负载和失败边界不同，行为/搜索/AI 可独立降级；本地开发代价也被脚本和统一契约控制。
- 常见误区：说服务越多越先进，忽略九 JVM 的内存和运维成本。

### 2. 服务边界如何确定？
- 核心答案：按用户、自媒体稿件、正式文章、行为、搜索、调度、后台、AI 的业务所有权，而非按表或页面。
- 常见误区：共享数据库表并让所有服务直接 Mapper 访问。

### 3. common、model、feign-api 为什么拆开？
- 核心答案：横切实现、数据契约、远程接口变化原因不同；业务服务只单向依赖它们。
- 常见误区：把所有业务 Service 塞进 common 形成隐式单体。

### 4. 如何禁止循环依赖？
- 核心答案：服务间不做 Maven 直接依赖，通过 feign-api 或 Kafka；父 POM 统一版本。
- 常见误区：只看 Maven 没有 cycle，却在 common 中反向引用业务模块。

### 5. 为什么固定 Java 21？
- 核心答案：与 Boot 3.5 技术线匹配，父 POM Enforcer 要求 `[21,22)`，构建环境可复现。
- 常见误区：release=21 就认为 Maven 运行 JDK 也是 21。

### 6. 为什么 Java 不容器化？
- 核心答案：项目目标是 Windows IDEA/JVM 调试，Docker 只承载基础设施；这是开发拓扑决策，不是技术限制。
- 常见误区：把 Nginx dist 验收描述成全栈生产部署。

### 7. 版本如何治理？
- 核心答案：父 properties/dependencyManagement 对齐 Boot、Cloud、Alibaba、AI BOM，子服务不重复声明版本。
- 常见误区：所有组件直接用 latest。

### 8. 为什么 Maven Wrapper？
- 核心答案：固定 Maven 3.9.10，使开发机和 CI 使用同一构建器。
- 常见误区：Wrapper 能固定 JDK；JDK 仍需 JAVA_HOME/工具链管理。

## 状态机与一致性

### 9. 发布的真相源是谁？
- 核心答案：MySQL 的稿件/文章状态与任务记录；MinIO、ES、摘要都是派生能力。
- 常见误区：以 ES 文档或对象是否存在判断发布权威状态。

### 10. CAS 解决什么？
- 核心答案：只允许预期状态/版本的单次推进，阻止并发审核、重复发布和旧 AI 结果覆盖。
- 常见误区：把 CAS 等同于完整分布式事务。

### 11. 为什么不用分布式事务？
- 核心答案：MinIO、ES、AI 等难以统一参与，长事务降低可用性；采用本地原子提交和异步补偿。
- 常见误区：说最终一致性天然简单或不需要状态表。

### 12. outbox 如何避免双写丢失？
- 核心答案：业务变更和 outbox 同一 MySQL 事务提交，投递器只处理持久记录。
- 常见误区：先提交业务再直接 send Kafka，进程崩溃会丢事件。

### 13. outbox 会重复投递吗？
- 核心答案：会，系统按至少一次设计；Consumer 用 eventId/版本/终态幂等。
- 常见误区：追求不现实的 exactly-once 端到端承诺。

### 14. MinIO 写成功、数据库失败怎么办？
- 核心答案：确定性 objectKey 让重试覆盖同一对象；状态和补偿决定最终发布，不生成随机垃圾对象。
- 常见误区：每次重试生成新 UUID Key。

### 15. 发布失败为何不能直接回 DRAFT？
- 核心答案：会丢失已审核和外部副作用证据；`PUBLISH_FAILED` 明确可恢复语义。
- 常见误区：用通用 ERROR 字段代替领域状态。

### 16. 定时发布如何防重复？
- 核心答案：Redis ZSet 提供到期候选，MySQL 任务/状态 CAS 决定唯一执行，XXL 扫描补偿遗漏。
- 常见误区：只靠 Redis remove 保证一次执行。

### 17. 如何处理旧消息？
- 核心答案：消息带 auditVersion/summaryVersion，Consumer 与当前版本 CAS；旧版本标记 STALE 或忽略。
- 常见误区：只用时间戳猜测新旧。

### 18. 精确恢复为何优于全量 backfill？
- 核心答案：减少非目标数据变更和 Provider 费用，双 CAS 只重开目标文章当前版本的 FAILED 任务。
- 常见误区：直接更新所有 FAILED 或手改 retryCount。

## Redis、Kafka 与行为

### 19. 点赞为何用 Lua？
- 核心答案：关系判断、计数、pending 必须原子；Lua 防并发 check-then-act。
- 常见误区：MULTI 能自动处理所有条件分支且无需重试设计。

### 20. 同用户重复点赞怎样处理？
- 核心答案：Lua 检查 relation，只有状态改变才调整计数并生成待持久化事件。
- 常见误区：每个 200 都让计数 +1。

### 21. 如何保证计数不为负？
- 核心答案：取消只对已存在关系生效，Lua 同步约束关系与计数；数据库聚合按幂等事件收敛。
- 常见误区：只在前端隐藏重复点击。

### 22. pending Hash 的作用？
- 核心答案：Kafka 发送失败时保留待投递载荷，恢复后重投，避免 Redis 已成功而消息丢失。
- 常见误区：把 pending 当永久真相且不清理。

### 23. eventId 唯一键放在哪里？
- 核心答案：持久化事件日志/处理表唯一约束，业务更新与记录同一事务。
- 常见误区：仅在 JVM Set 去重，重启后失效。

### 24. VIEW 为什么批量？
- 核心答案：浏览是高频可聚合增量，Consumer 批量降低数据库写放大，同时 eventId 保证不重计。
- 常见误区：批处理就可以丢掉单事件身份。

### 25. Kafka 至少一次意味着什么？
- 核心答案：重复比丢失更可接受，消费者必须幂等，offset 只在本地事务成功后推进。
- 常见误区：Broker 开启幂等 Producer 就实现端到端 exactly-once。

### 26. advertised.listeners 为什么会导致“初连成功后失败”？
- 核心答案：bootstrap 返回元数据地址；Host 若收到 `kafka:29092` 就无法解析，所以需 INTERNAL/EXTERNAL 两套 listener。
- 常见误区：只测试端口 TCP 可达。

### 27. DLT 的价值？
- 核心答案：有限重试后隔离毒消息并保留审计，避免分区永久阻塞。
- 常见误区：进 DLT 等于自动修复完成。

### 28. Kafka 故障如何验证？
- 核心答案：停 Broker 后发真实请求，检查 pending/业务状态；恢复后观察 lag=0、pending=0、MySQL 精确增量。
- 常见误区：只看容器重新 healthy。

## 搜索与热点

### 29. 为什么 ES 不是文章真相源？
- 核心答案：它是可重建查询投影；文章详情和状态以 MySQL 为准。
- 常见误区：发布成功必须同步等待 ES refresh。

### 30. 搜索故障为何返回 503？
- 核心答案：不能伪造空结果；明确能力不可用，同时不影响普通文章读取。
- 常见误区：捕获异常后返回空列表造成“没有内容”的误导。

### 31. 高亮如何防 XSS？
- 核心答案：后端返回片段，前端解析允许的高亮标记并转义其他文本，不直接 `v-html`。
- 常见误区：认为 ES 返回内容天然可信。

### 32. 联想为何用 edge-ngram？
- 核心答案：索引期生成前缀 token，查询期使用标准分析，适合前缀联想。
- 常见误区：查询和索引两侧都盲目 ngram 导致噪声。

### 33. 搜索历史为何放 MySQL？
- 核心答案：每用户数据量小、需要持久删除和所有权边界，避免为单一功能引入 MongoDB。
- 常见误区：看到历史就默认 NoSQL。

### 34. 热点评分为何统一？
- 核心答案：实时与离线若公式不同会互相覆盖抖动，共享评分服务保证同口径。
- 常见误区：Streams 与 XXL 各复制一套 magic number。

### 35. 为什么 Streams 不累加行为事件？
- 核心答案：Lua 已更新 counter；Streams 只触发按绝对值重算，防重复与双计数。
- 常见误区：事件到一次就 `ZINCRBY`，重放会漂移。

### 36. 离线热点如何原子替换？
- 核心答案：写临时 ZSet 完整成功后 rename 到正式 Key，读者不会看到半份榜单。
- 常见误区：先删除正式 Key 再逐条填充。

## AI 与 SSE

### 37. DFA 和大模型如何分工？
- 核心答案：DFA 处理确定性敏感词并节省调用；Qwen 处理语义/图片；人工处理不确定与异常。
- 常见误区：让模型覆盖所有规则或让 DFA 处理语义判断。

### 38. 如何约束模型结构化输出？
- 核心答案：明确 schema，converter 解析并做必填、枚举、置信度范围校验；失败映射 502 并转人工。
- 常见误区：从自然语言中用 contains("PASS") 猜结论。

### 39. 为什么 AI 失败不能默认通过？
- 核心答案：可用性异常不等于内容安全；默认 PASS 会把基础设施故障变成审核漏洞。
- 常见误区：为了自动化率牺牲安全边界。

### 40. auditVersion 何时递增？
- 核心答案：稿件编辑后重新提交时在事务内递增并创建对应任务。
- 常见误区：每次 Consumer 重试都递增版本。

### 41. 摘要为何独立于发布？
- 核心答案：摘要是增强信息，Provider 延迟/费用不应进入发布事务；FAILED 可后续恢复。
- 常见误区：AI 超时导致整篇文章撤回。

### 42. 短文自适应下限解决什么？
- 核心答案：短正文无法在不虚构的前提下生成固定 80 字；仅短文降低下限，仍保留 160 上限与正常文章 80 下限。
- 常见误区：直接取消所有长度校验。

### 43. SSE 事件契约是什么？
- 核心答案：meta 声明上下文，chunk 增量，done 正常完成，error 给业务码/traceId。
- 常见误区：把任意纯文本拼接当稳定协议。

### 44. SSE 同步异常为何特殊？
- 核心答案：`text/event-stream` 下 JSON advice 可能无 converter；专用 advice 返回真实 HTTP 状态和一个 error frame。
- 常见误区：所有错误都强行 HTTP 200。

### 45. 如何证明取消有效？
- 核心答案：客户端 Abort 后服务 Flux 收到 cancel、释放 permit，紧随其后的合法请求能完成。
- 常见误区：只关闭浏览器 UI，不观察服务端资源。

### 46. 如何控制 AI 成本与并发？
- 核心答案：Gateway Sentinel + AI bulkhead + timeout/有限 retry；非法输入在 Provider 前失败，health 不调用模型。
- 常见误区：对 400/401 无限重试。

## 安全、测试与生产化

### 47. Gateway 如何建立信任边界？
- 核心答案：验证 Bearer JWT，删除客户端用户头，从 claims 重建并透传 traceId。
- 常见误区：下游直接相信浏览器传来的 userId。

### 48. `/internal/**` 为什么返回 404？
- 核心答案：Gateway 不建立外部路由并显式拒绝，减少接口枚举；内部 Feign 仍可按服务名调用。
- 常见误区：认为 404 等于生产级零信任。

### 49. 401/403/409/429/503 有何区别？
- 核心答案：未认证、无权限、状态冲突、限流、依赖能力不可用；前端动作和重试建议不同。
- 常见误区：统一显示“网络错误”或在 429 后乐观更新。

### 50. Nacos 故障时规则会怎样？
- 核心答案：客户端保留最后加载配置并尝试重连；认证请求不应逐次依赖 Nacos。
- 常见误区：配置中心短暂不可用就清空规则。

### 51. 如何管理 secret？
- 核心答案：仓库只留变量名/本地非敏感默认，`.env` 忽略，Qwen Key 进程环境注入，日志不记录正文/Key/Provider 全响应。
- 常见误区：把占位符替换为真实密码后提交。

### 52. 健康检查为什么不够？
- 核心答案：UP 只证明探针，不证明生产消费、数据一致或恢复；需要真实读写和状态核对。
- 常见误区：`docker compose ps` healthy 就宣布验收完成。

### 53. 如何解读 2,112 RPS？
- 核心答案：99.77% 是快速 429，不是业务吞吐；应报告正常成功区间和放行量。
- 常见误区：只取总请求数除时间。

### 54. 当前压测能证明什么？
- 核心答案：在指定单机/短时/Sentinel 条件下的功能延迟、限流行为和无 5xx；不能外推生产容量。
- 常见误区：从 localhost 60 秒测试推导 SLA。

### 55. JVM 72 样本无 Full GC 意味什么？
- 核心答案：该观察窗未见 Full GC；不代表长期无泄漏。九 JVM 理论 MaxHeap 总和仍过高。
- 常见误区：据此声称 GC 已优化完毕。

### 56. 原项目与新项目的贡献如何区分？
- 核心答案：原项目已有领域、静态化、ES、Kafka/Streams、XXL、DFA方向；新项目贡献是现代重写及状态、幂等、AI、安全、恢复和验证。
- 常见误区：把原系统已有功能全部说成自己原创。

### 57. 最值得继续优化什么？
- 核心答案：服务身份/mTLS、基础设施集群、集中 metrics/tracing/alert、连接池与堆上限、长时 soak、备份恢复、CI/CD。
- 常见误区：没有证据先盲目加缓存或索引。

### 58. 如何证明原项目未被修改？
- 核心答案：全过程只读参考，最终检查其 Git porcelain 为空；新项目扫描不含原路径硬编码。
- 常见误区：只说“我没改”但不留 Git 证据。

### 59. 为什么不实现评论？
- 核心答案：阶段目标聚焦已分析核心域，评论不是当前实际实现；文档和简历不虚构 API。
- 常见误区：为了功能列表完整而声称不存在的能力。

### 60. 你如何定义项目完成？
- 核心答案：代码、构建、真实链路、故障恢复、安全扫描和文档口径全部一致，并明确剩余生产化边界。
- 常见误区：功能演示一次成功就算完成。
